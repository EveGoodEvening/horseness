# Codex integration

Horseness supports the digest-verified `@openai/codex@0.144.1-linux-x64` distribution. The executable member is `vendor/x86_64-unknown-linux-musl/bin/codex` with SHA-256 `a96f944d1a596dbfb7fdd84f482be5c50e34b04bb371126840d873e4ebf26902`.

The native bundle is a real Codex plugin named `horseness-codex`. It contributes `.codex-plugin/plugin.json`, `.mcp.json`, an `AGENTS.md` context contribution, the `horseness-worker` skill, and the trusted `horseness-worker` MCP server. For pinned Codex 0.144.1, `.mcp.json` sets `cwd: "."` so the host resolves the working directory against the installed plugin root while the relative server argument remains valid. The declaration forwards only the three Horseness runtime socket, nonce, and thread-claim variables. Native `plugin/installed` and `plugin/read` must identify the enabled `horseness-codex@horseness-c18` cache record. The shipped manifest remains deterministic at its package version; the temporary marketplace copy receives a valid SemVer build-metadata version derived from the shipped contribution package digest so Codex cannot reuse stale installed plugin/MCP bytes for the stable plugin ID. The smoke independently binds both the shipped contribution digest and the exact cache-busted installed bytes.

Under ADR 0006, the smoke uses the invoking OS user's existing logged-in Codex subscription session. The verified app-server receives a minimal allowlisted environment: verified binary/runtime `PATH`, required `HOME`/`CODEX_HOME`, locale, bounded temporary paths, and reviewed nonsecret Codex controls. Secret-shaped names and explicit provider API keys, cloud/CI credentials, and proxy credentials are stripped. Horseness never opens, copies, hashes, exports, logs, or persists Codex authentication state and never runs provider logout. Missing or unusable native authentication without environment credentials fails closed with a stable redacted reason.

`pnpm run host:smoke:codex` acquires and verifies the pinned archive and executable, validates pinned app-server schemas under the same stripped native environment, hashes every shipped and installed contribution after realpath/lstat confinement checks, and installs/discovers the plugin through Codex's native marketplace lifecycle. Initial, resume, and fork claims each use a fresh app-server process so the plugin MCP child inherits exactly one claim before startup. The fork is ephemeral; the initial thread intentionally remains materialized because pinned `thread/resume` cannot reopen an ephemeral thread and exposes no compatible `ephemeral` field. Initial, resume, fork, and turn requests set approval policy `never` and permissions `:read-only`. Initial and turn requests select no environments, initial requests supply no dynamic tools, and direct dotted config overrides disable hosted web search, Apps/MCP Apps, shell/unified execution, code modes, standalone/cached/request web search, tool suggestions, multi-agent/fanout, environment and collaboration-mode instruction injection, and automatic skill instructions while leaving `features.plugins=true`. No unsupported profile, default-tools, or `tools.web_search` configuration is used. Turn input carries the structured `plugin://horseness-codex@horseness-c18` mention, the verified installed skill item, exact text, and application-role additional context built from independently verified installed `AGENTS.md` and immutable attempt context bytes. Empty environments remove command, file-change, image, permission-request, and environment-backed tools; empty dynamic tools remove client tools; hosted web search is disabled. Native MCP inventory must still report ready, and the model turn must contain exactly one executing item: the plugin-attributed Horseness MCP call.

One model turn emits a real `mcpToolCall` for `mcp__horseness-worker__horseness_worker_return` carrying exactly five bound scenarios. The trusted adapter-kit/SDK return path publishes output and evidence, submits an authenticated receipt and sealed proposal, starts and resumes decision observation, and surfaces `accepted`, `rejected`, `conflicted`, `quarantined`, and `approval_required`. The accepted scenario advances the real authority to revision 1 with document `{ "value": 2 }`.

After that batch the smoke terminates the app-server and adapter runtime, reopens durable retained and thread-binding state in new instances, starts a fresh pinned app-server process with the resume claim, re-verifies installed plugin provenance, resumes the same native thread, reconciles/reattaches the original attempt, then starts another fresh process with the fork claim and forks a distinct ephemeral native thread bound to the pre-registered second capability.

Native uninstall uses an exact-schema, owner-private file-and-parent-fsynced journal. Its absolute private kill-switch path is checked before every runtime request. Startup recovery idempotently removes only the journal-owned native plugin and marketplace before authority revocation, then completes. Crash injections cover kill-switch persistence, internal discovery removal, `discovery_disabled`, and `authority_revoked`; every recovery recreates the app-server, socket server, retained authority, runtime, and session bindings from durable disk, rejects a valid unconsumed cached claim, and proves fresh native server/tool inventory is absent. Preflight rejects collisions with the fixed C18 plugin or marketplace IDs in the invoking user's `CODEX_HOME`; failure cleanup is journal-driven, verified, redacted, and never touches unrelated native state.

The live receipt is host- and candidate-bound and records only nonsecret provenance, including the shipped package/contribution digests, digest-derived installed plugin version, installed package digest, resolved MCP declaration digest, model, command/scenario digests, immutable Horseness bindings, output/evidence/receipt/proposal digests, timing, redaction audit, and terminal reason. It has finite scenario, provider-operation, turn, tool, wall-clock, and byte bounds; ADR 0006 intentionally defines no monetary or token-cost cap.

The shared C11 fixture manifest retains its historical pre-ADR credential-reference `livePolicy`. C18 does not consume that legacy policy: under accepted ADR 0006 its live smoke uses the invoking user's existing Codex subscription session, applies its own finite wall-clock/scenario/turn/tool/byte bounds, and never reads, copies, hashes, or logs provider authentication state.
