# Codex integration

Horseness supports the digest-verified `@openai/codex@0.144.1-linux-x64` distribution. The executable member is `vendor/x86_64-unknown-linux-musl/bin/codex` with SHA-256 `a96f944d1a596dbfb7fdd84f482be5c50e34b04bb371126840d873e4ebf26902`.

The native bundle is a real Codex plugin named `horseness-codex`. It contributes `.codex-plugin/plugin.json`, `.mcp.json`, an `AGENTS.md` context contribution, the `horseness-worker` skill, and the trusted `horseness-worker` MCP server. Codex 0.144.1 does not interpolate a plugin-root token for the contribution-relative stdio path, so each thread uses the supported absolute `config.mcp_servers` override. That override is derived only after native `plugin/installed` and `plugin/read` identify the enabled `horseness-codex@horseness-c18` installed cache record and every installed manifest, declaration, context, skill, and server byte matches shipped metadata. The skill path and developer instructions likewise come only from those verified installed records. The pinned host reports a nullable native tool-item `pluginId` under this override; receipts record null with reason `PINNED_HOST_THREAD_OVERRIDE` rather than claiming attribution.

Under ADR 0006, the smoke uses the invoking OS user's existing logged-in Codex subscription session. Horseness never opens, copies, hashes, exports, logs, or persists Codex authentication state and never runs provider logout. Missing or unusable native authentication fails closed with a stable redacted reason. Horseness attempt authority remains a separate opaque, least-privilege capability.

`pnpm run host:smoke:codex` acquires and verifies the pinned archive and executable, generates and validates the pinned app-server schemas, independently hashes every shipped and installed contribution, and installs/discovers the plugin through Codex's native marketplace lifecycle. Every native thread gets a trusted one-time claim in its MCP process environment. Only after `thread/start`, `thread/resume`, or `thread/fork` returns does the runtime immutably bind that claim to the actual thread identity, exact capability/ForkPin, and verified context; the MCP batch must present the claim and the runtime forwards the resolved thread through every delivery. Unknown, reused, or substituted claim/thread/capability tuples fail closed.

One model turn emits a real `mcpToolCall` for `mcp__horseness-worker__horseness_worker_return` carrying exactly five bound scenarios. The trusted adapter-kit/SDK return path publishes output and evidence, submits an authenticated receipt and sealed proposal, starts and resumes decision observation, and surfaces `accepted`, `rejected`, `conflicted`, `quarantined`, and `approval_required`. The accepted scenario advances the real authority to revision 1 with document `{ "value": 2 }`.

After that batch the smoke terminates the app-server and adapter runtime, reopens durable retained and thread-binding state in new instances, starts a new pinned app-server, re-verifies native installed-plugin inventory, resumes the same native thread, reconciles/reattaches the original attempt, and then forks a distinct native thread bound to the pre-registered second capability.

Native uninstall uses an owner-private file-and-parent-fsynced journal. Its kill switch is checked before every runtime request. Startup recovery idempotently disables native plugin/marketplace discovery and the absolute thread override before authority revocation, then completes. Crash injections cover kill-switch persistence, internal discovery removal, `discovery_disabled`, and `authority_revoked`; each recovery recreates the app-server/runtime from disk, rejects cached claims, and proves fresh native plugin/MCP/skill inventory is absent. Removing Horseness never logs out or claims to revoke the user's Codex subscription session.

The live receipt is host- and candidate-bound and records only nonsecret provenance, model, command/scenario digests, immutable Horseness bindings, output/evidence/receipt/proposal digests, timing, redaction audit, and terminal reason. It has finite scenario, provider-operation, turn, tool, wall-clock, and byte bounds; ADR 0006 intentionally defines no monetary or token-cost cap.
