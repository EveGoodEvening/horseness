# Claude Code native integration

`@horseness/adapter-claude` supports exactly the verified Linux x64 `@anthropic-ai/claude-code-linux-x64@2.1.228` distribution. The live smoke acquires the frozen registry archive, verifies its registry integrity, archive SHA-256, executable member SHA-256, and same-distribution validation interface, then executes only the copied verified `claude` binary.

Authentication follows ADR 0006. The binary runs as the invoking OS user and may use that user's already logged-in Claude Code subscription session. Horseness does not inspect, read, copy, hash, back up, export, log, or persist auth stores, tokens, cookies, headers, account identifiers, or secret-derived values. The session provides provider authentication and billing only; the attempt capability remains a separate opaque Horseness grant. A missing, expired, rejected, interactive-login-required, model-unavailable, timed-out, or otherwise unusable session hard-fails with a stable redacted reason. Uninstall revokes only Horseness authority and does not log out or alter the provider-owned session.

The shipped real Claude plugin contains a manifest, slash command, bounded worker agent, worker skill, SessionStart hook, and namespaced stdio MCP server. SessionStart injects the immutable attempt context. The initial real Claude session makes one native MCP tool call with an exact bounded batch of five distinct scenario capability references. The trusted MCP server validates every scenario's byte/media contract and sends one batch to the adapter-owned runtime over an owner-confined authenticated local socket. The runtime executes five complete `WorkerReturnV1` deliveries: it collects each binding-valid receipt, asks authority code to seal each proposal, and delegates publication, receipt submission, proposal submission, and two-stage resumable decision observation to the authority client. The socket response is strictly capped at 8 KiB and contains only nonsecret evidence required by the native smoke: session and binding identifiers, each authority outcome, receipt/proposal/output/evidence digests, and the accepted canonical revision/state digest. Full `WorkerReturnV1`, proposal, receipt, publication, resume-token, and verbose decision objects remain in the private retained authority and are not duplicated through MCP. The MCP tool returns one copy of that compact batch evidence rather than duplicating it as structured content.

A private durable retained authority binds workspace, run, task, attempt, generation, ForkPin, context, output, evidence, receipt, proposal, resume token, and decision. A separate owner-private session-binding journal records the initial Claude session and every explicitly pre-registered fork transition. SessionStart is the trusted registration boundary: startup creates the first immutable session-to-attempt mapping, ordinary resume can only reuse its source mapping, and a new fork session can consume only the pre-registered branch entry. Unknown resume sources, session substitution, branch substitution, and attempts to overwrite a persisted mapping fail closed; shared context-file rewriting is not an authority mechanism.

Run `pnpm run host:smoke:claude`. The smoke never sets `CLAUDE_CONFIG_DIR`, changes the user's real Claude plugin registry/config, or copies/inspects the native authentication store. It isolates the workspace, exact temporary plugin copy, MCP sockets and retained/runtime state, HOME-neutral outputs, and temporary files. The initial contribution-bearing invocation discovers only that copied plugin root through `--plugin-dir` and performs exactly one worker tool call containing exactly five scenarios. Policy, conflict, and quota preconditions cause `SQLiteAuthority` and `AdmissionService` themselves to produce accepted, rejected, conflicted, quarantined, and approval-required, with accepted alone advancing canonical state. Minimal real `--resume` and `--resume ... --fork-session` marker invocations then prove SessionStart binding and context without worker tool calls. After atomic discovery disablement and grant revocation, one minimal native initialization invocation proves the plugin and MCP tool absent. Stable subscription rate-limit and native-host failures remain fail-closed. Exact scenario count and one-tool-call-per-provider-invocation are enforced; no monetary or token-cost cap is claimed.

Uninstall first atomically persists and fsyncs the retained kill-switch state, which disables discovery even if the exact temporary `--plugin-dir` path still exists. It then atomically renames that discovery path out of service and fsyncs its parent before revoking runtime/grant authority and persisting `authority_revoked`; only the verified plugin-free native restart permits `complete`. Crash-injection restarts after the kill-switch, discovery-disable, and authority-revocation boundaries prove discovery stays disabled and unfinished revocation resumes idempotently. Cached Horseness capabilities are rejected. Cleanup removes only smoke-owned temporary plugin bytes and state. It never edits the user's Claude registry/config, logs out, or modifies the provider-owned subscription session. Success emits validated `ClaudeSubscriptionLiveReceiptV1`, including the required literal `authMode: "existing-user-subscription-session"`, observed model, candidate HEAD/tree, exact command and scenario digest, archive/member/executable/package/contribution provenance, every immutable binding/ForkPin/context/receipt/proposal/output/evidence digest, bounded timing, terminal reason, and a redaction audit; missing or substituted authentication modes fail validation.
