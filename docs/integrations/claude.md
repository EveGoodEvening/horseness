# Claude Code native integration

`@horseness/adapter-claude` supports exactly the verified Linux x64 `@anthropic-ai/claude-code-linux-x64@2.1.228` distribution. The live smoke acquires the frozen registry archive, verifies its registry integrity, archive SHA-256, executable member SHA-256, and same-distribution validation interface, then executes only the copied verified `claude` binary.

Authentication follows ADR 0006. The binary runs as the invoking OS user and may use that user's already logged-in Claude Code subscription session. Horseness does not inspect, read, copy, hash, back up, export, log, or persist auth stores, tokens, cookies, headers, account identifiers, or secret-derived values. The session provides provider authentication and billing only; the attempt capability remains a separate opaque Horseness grant. A missing, expired, rejected, interactive-login-required, model-unavailable, timed-out, or otherwise unusable session hard-fails with a stable redacted reason. Uninstall revokes only Horseness authority and does not log out or alter the provider-owned session.

The shipped real Claude plugin contains a manifest, slash command, bounded worker agent, worker skill, SessionStart hook, and namespaced stdio MCP server. SessionStart injects the immutable attempt context. The native MCP tool accepts one trusted attempt capability plus bounded output and evidence, validates their byte and media contracts, and sends their digests to the adapter-owned runtime over an owner-confined authenticated local socket. The runtime collects the binding-valid receipt, asks authority code to seal the proposal, constructs the complete `WorkerReturnV1`, and delegates publication, receipt submission, proposal submission, and two-stage resumable decision observation to adapter-kit.

A private durable retained authority binds workspace, run, task, attempt, generation, ForkPin, context, output, evidence, receipt, proposal, subscription, resume token, and decision. It serializes cross-instance callbacks, checkpoints each completed delivery phase durably, resumes after process interruption without repeating completed effects, and rejects capability or canonical tuple substitution. Native session identity is retained separately from Horseness authority: `--resume` must preserve the Claude session and attempt binding, while `--fork-session` must create a new Claude session mapped to the explicitly registered second attempt and ForkPin.

Run `pnpm run host:smoke:claude`. The credentialed smoke has finite scenario, wall-clock, turn, native-tool-call, context, stream, output, and evidence bounds, but deliberately has no monetary or token-cost cap. It validates plugin discovery and inventory, launches the real noninteractive headless host, inspects the system/init stream and actual MCP `tool_use`/`tool_result`, drives authority-produced accepted, rejected, conflicted, quarantined, and approval-required decisions, proves accepted canonical advance, exercises resume, fork, restart, reconciliation, durable recovery, contribution removal/reload absence, and Horseness grant revocation. It never substitutes a harness-issued MCP call for the native Claude invocation.
